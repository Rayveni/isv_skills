## MoSCoW-правила

_Источник истины — [references/requirements-taxonomy.md](references/requirements-taxonomy.md) (раздел «MoSCoW»). Этот раздел — сокращённая копия для удобства чтения; при расхождениях верно правило в taxonomy._

- Оценка — атрибут каждого требования (BR, StR, FR, NFR, BRU) во всех документах.
- CON, ASM, DEP, INT, DAT — контекст, не деливерабл: не приоритизируются и в правило 40% не входят; RISK и GLOSS не приоритизируются вовсе.
- Правило «Must ≤ 40%» и обоснования для каждого M/W — только для этого документа; 40% считается по требованиям-деливераблам (BR, StR, FR, NFR, BRU — включая NFR).
- Каждое требование — одна проверяемая формулировка.
- Типы: BR, StR, FR, NFR, BRU, CON, ASM, DEP, INT, DAT. ID совпадают с ID в спецификации и AI-контексте.
- У каждого требования: уникальный ID, тип, источник, приоритет, способ проверки, связь с бизнес-целью.
- Каждое NFR несёт категорию, измеримую метрику и цель; неизмеримые требования переформулированы или в открытых вопросах.
- Критерии приёмки пишутся в формате Given-When-Then; user stories — «Как <роль>, я хочу <действие>, чтобы <ценность>».
